# 実務ワークフロー実践プレイブック

この教材は、AI-HUBのWF-001〜WF-010の各工程について「次に何をするか」「何を確認・記録するか」「どの状態なら次へ進めるか」を定義します。

## 共通ルール

1. 対象・担当・時刻・依頼番号を最初に特定する。
2. 最初は読み取り専用の確認から始め、事実と推測を分ける。
3. 変更・削除・停止・権限付与・隔離・復元は、承認・影響・戻し方を確認する。
4. 実行したコマンド、端末、時刻、結果を記録する。秘密情報・認証トークン・個人情報を不用意に記録しない。
5. 影響が大きい、セキュリティ事故の疑いがある、判断できない場合は、早期に責任者へ連絡する。

## WF-001 問い合わせ受付

| 工程 | 次にすること | 記録・確認 | 次へ進む条件 |
|---|---|---|---|
| 受付 | 依頼者、連絡先、受付時刻、希望を確認 | チケット番号、連絡先 | 受付記録が作成済み |
| 対象/利用者 | 対象システム、端末、利用者、拠点を特定 | 資産番号、対象名 | 対象が一意に分かる |
| 発生時刻/エラー | 発生時刻、エラー全文、再現頻度、直前操作を聞く | スクリーンショット等の証跡（機密を除く） | 症状を再現・説明できる |
| 影響範囲 | 何人・何台・どの業務か確認 | 影響人数、業務、回避策 | 優先度が判断できる |
| ナレッジ検索 | エラー文・システム名・関連索引で既知事例を検索 | 参照した索引と一致点 | 適用可能な既知手順を判断 |
| 対応/引継ぎ | 権限内の手順で対応。範囲外は担当へ引継ぐ | 実施内容、承認、結果 | 対応または担当引継ぎ済み |
| 利用者確認 | 依頼者に再操作を依頼 | 確認者、時刻、結果 | 利用者が正常を確認 |
| 完了記録 | 結果・原因・未解決事項を記録 | チケット、証跡、関連索引 | 記録と連絡が完了 |

## WF-002 障害対応

| 工程 | 次にすること | 記録・確認 | 次へ進む条件 |
|---|---|---|---|
| 検知 | 監視アラート・利用者連絡・ログを確認 | 検知時刻、アラートID | 事象を特定 |
| 初動 | 影響拡大を避け、担当者・責任者へ連絡 | 初動時刻、担当 | 初動体制が明確 |
| 影響範囲 | 利用者・端末・拠点・業務を確認 | 対象数、停止機能 | 影響範囲を記録 |
| 重大度 | 社内基準で優先度を判断 | 判断根拠 | 優先順位と連絡先が決定 |
| 連絡 | サービス責任者・関連チームへ共有 | 誰に、いつ、何を伝えたか | 必要な関係者が認識 |
| 証拠保全 | ログ・時刻・エラー・状態を保存 | ログ保存先、ハッシュ等 | 証跡が保全されている |
| 原因切り分け | 直近変更、DNS、経路、ポート、アプリログ、DB依存を段階確認 | コマンド、実行端末、出力 | 原因候補と未確認事項を整理 |
| 承認済み復旧 | 承認された手順・変更範囲で復旧 | 承認番号、作業者、前後状態 | 対応結果を記録 |
| 動作確認 | 監視・ヘルスチェック・利用者操作を確認 | テスト結果、確認者 | 業務機能が復旧 |
| 報告 | 時系列、影響、原因、対応、残課題を報告 | 報告書、担当・期限 | 責任者レビュー済み |

ネットワークの読み取り確認例（対象環境に合わせて使用）：

```powershell
Get-Date
Get-NetIPConfiguration
Resolve-DnsName <接続先ホスト名>
Test-NetConnection <接続先ホスト名> -Port 443
```

Javaアプリの確認例：

```powershell
jcmd -l
jcmd <PID> Thread.print
Select-String -Path <ログファイル> -Pattern "ERROR|Exception"
```

PID・ログパスを確認してから実行する。スレッドダンプ等には内部情報が含まれる場合があるため、保管先と共有範囲を制限する。

## WF-003 入社アカウント発行

1. 人事等の正式申請を確認し、氏名・社員ID・所属・開始日を照合。
2. 標準ロールと必要システムを確認。申請にない特権を追加しない。
3. 上長・システム所有者の承認を確認。
4. ID作成・MFA登録を規定手順で実施。初期パスワードを安全に配布。
5. 端末・メール・VPN・業務アプリを準備。
6. 本人または依頼元にログイン・業務利用確認を依頼。
7. 作成者・承認・権限・時刻・資産番号を台帳へ記録。

参照確認例（ActiveDirectoryモジュールがあり、許可された管理端末で使用）：

```powershell
Get-ADUser -Identity <ユーザーID> -Properties Enabled,MemberOf
```

## WF-004 退職・異動対応

1. 正式な人事通知と対象ID、停止・変更日時を照合。
2. 対象システム、共有データ、所有資産、委任権限を一覧化。
3. 人事・上長・システム所有者の承認を確認。
4. 指定時刻にアカウント停止・権限変更を規定手順で実施。
5. セッション・VPN・トークン等の扱いをセキュリティ手順に従って処理。
6. 業務データの所有者・引継ぎ先・保管要件を確認。
7. 端末・貸与品を回収し、台帳と作業記録を更新。

参照確認例：

```powershell
Get-ADUser -Identity <ユーザーID> -Properties Enabled,MemberOf
Get-ADPrincipalGroupMembership -Identity <ユーザーID>
```

アカウント停止等の変更コマンドは、この教材では自動実行しない。日時・対象・承認を二重確認して組織の正式手順で行う。

## WF-005 権限追加・変更

1. 申請者・対象ID・対象リソース・必要業務・希望期限を確認。
2. 既存権限と重複・競合・特権の有無を確認。
3. データ所有者・上長の承認を取得。
4. 最小権限、期限付き付与、職務分離を検討。
5. 承認範囲だけ付与し、実施前後の状態を記録。
6. 利用者・依頼元に動作確認を依頼。
7. 期限到来時の解除と定期棚卸しを登録。

参照確認例：

```powershell
Get-ADPrincipalGroupMembership -Identity <ユーザーID>
Get-ADGroupMember -Identity <グループ名>
```

## WF-006 システム変更

1. 変更目的・対象・希望日時・作業者・影響サービスを申請。
2. 依存システム・利用者・停止時間・リスクを調査。
3. 検証環境でテストし、期待結果と中止条件を決める。
4. 変更責任者・CAB等、社内規程の承認を得る。
5. バックアップ・復旧手順・切戻し判断者・連絡先を確認。
6. 作業時間内に承認済み手順だけ実行。
7. サービス・ログ・監視・利用者の確認を行う。
8. 成否・差分・残課題を記録し、変更チケットを閉じる。

読み取り確認例：

```powershell
Get-Service -Name <サービス名>
Get-WinEvent -FilterHashtable @{LogName="System";StartTime=(Get-Date).AddHours(-2)} -MaxEvents 50
```

## WF-007 バックアップ・復元

1. 対象データ、バックアップ方式、世代、取得時刻、保管先を確認。
2. 実行ログだけでなく、容量・整合性・復元テスト結果を確認。
3. 復元依頼者、対象時点、復元先、上書き有無、承認を確認。
4. 本番上書き前に隔離された検証先でテスト復元。
5. ファイル数・サイズ・チェックサム・アプリ整合性を確認。
6. 本番復元は責任者承認と製品手順に従う。
7. 復元後に利用者・アプリ所有者が確認し、証跡を保存。

ファイル一覧の参照例：

```powershell
Get-ChildItem -LiteralPath <バックアップ確認用パス> -File |
  Select-Object Name,Length,LastWriteTime
```

## WF-008 セキュリティ事故対応

1. 検知時刻・端末・利用者・アラートIDを記録。
2. 感染・漏えい・不正アクセスの可能性と影響を確認。
3. 直ちにセキュリティ窓口・責任者へ報告。
4. 指示に従い隔離・封じ込め。独断で初期化・削除・ログ消去しない。
5. ログ・ファイル・時刻等を証拠保全し、アクセスを制限。
6. 影響範囲・侵入経路・対象アカウント・データを調査。
7. 復旧は責任者の判断と承認された手順で行う。
8. 利用者連絡・再発防止・監視強化を記録。

参照例：

```powershell
Get-Date
Get-NetTCPConnection | Select-Object State,LocalAddress,LocalPort,RemoteAddress,RemotePort
Get-FileHash -Algorithm SHA256 -LiteralPath <証跡ファイル>
```

## WF-009 報告書作成

1. 事実と推測を分ける。「未確認」「調査中」を明記。
2. 発生・検知・連絡・調査・対応・復旧の時系列を整理。
3. 影響範囲、対象、業務影響、回避策を記載。
4. 実行した確認・コマンド・結果・証跡保存先を記載。
5. 原因は確定と仮説を区別。
6. 現在状態、残課題、担当者、期限、次回報告時刻を記載。
7. 責任者レビュー後、チケットと関連資料を紐付ける。

テンプレート：

```text
【件名】
【発生日時・検知日時】
【対象システム・範囲】
【事象（確認済み事実）】
【影響範囲・業務影響】
【時系列】
【確認内容・証跡】
【原因】確定／調査中
【実施対応・承認】
【現在の状態】
【未解決事項】
【次の対応・担当・期限】
```

## WF-010 再発防止

1. 暫定復旧と業務影響の解消を確認。
2. 時系列と証拠から直接原因・根本原因を分析。
3. 発生条件、検知できなかった理由、影響拡大要因を整理。
4. 技術・運用・監視・権限・教育の複数面で対策案を作る。
5. 対策ごとに担当者・期限・優先度・成功指標を決める。
6. テスト環境で検証し、変更承認後に展開。
7. 監視・手順書・ナレッジ・教育へ反映。
8. 一定期間後に再発率・アラート・利用者影響を確認。

## 共通の報告フォーマット

- 発生時刻／検知時刻：
- 対象・環境：
- 影響範囲：
- 実行した確認（コマンド・端末・時刻）：
- 確認できた事実：
- 原因候補（確定／仮説）：
- 実施した対応と承認：
- 現在の状態：
- 次の対応・担当・期限：
- 証跡の保存先：

## 学習時の使い方

各WFで、まず工程カードを1つ開き、実施内容を声に出して説明します。次に「記録・確認するもの」を自分で挙げ、最後に「次へ進む条件」を説明します。コマンドは検証環境で読み取りから練習し、変更系操作は組織の承認済み手順でのみ実施してください。
