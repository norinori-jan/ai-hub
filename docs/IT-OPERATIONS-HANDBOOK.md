# AI-HUB 社内ITナレッジセンター
版: 1.0 / 作成: 2026-11-25

## 目的
データベース、社内インフラ、セキュリティ、日常運用について、索引からすぐ探し、質問への回答・確認手順・障害対応・報告まで一貫して行うための実務ハンドブック。

> 本書は一般的な学習・運用ガイドです。実際の本番作業では、必ず自社の規程、承認、変更管理、製品バージョン、担当者の指示を優先してください。未承認の本番変更、データ削除、権限変更、証拠消去は行わないでください。

## 使い方
1. 索引コード（例: NW-002）または用語で探す。
2. 「一言説明」で意味をつかむ。
3. 「確認手順」で見る場所を確認する。
4. 障害時は「共通初動」から始める。
5. 作業後は報告テンプレートに記録する。
6. 判断できない場合は、影響範囲・発生時刻・エラー・実施済み確認を添えてエスカレーションする。

## 共通初動：障害が起きたら
1. **安全確保**：破壊的操作、再起動、設定変更を急いで行わない。セキュリティ疑いは社内の隔離手順を優先。
2. **事実確認**：発生時刻、対象システム、利用者、画面/エラー、直前の変更を記録。
3. **範囲確認**：単一ユーザー/部署/全社、単一機能/全機能を切り分け。
4. **影響評価**：業務停止、データ損失、情報漏えい、安全性を評価。
5. **証拠保全**：ログ、アラート、画面、チケット番号を保存。機密情報は規程に従って扱う。
6. **連絡・承認**：担当チーム、上長、セキュリティ窓口へ連絡。重大度に応じてエスカレーション。
7. **復旧**：承認済み手順・変更管理のもとで実施。
8. **確認・記録**：利用者確認、監視正常化、時系列、原因、再発防止を記録。

## よくある障害：確認フロー
| 症状 | まず確認 | 次に確認 | 避けること |
|---|---|---|---|
| 社内サイトに接続不可 | 自分だけか/複数人か、Wi-Fi/LAN | DNS、GW、VPN、FW、サーバー状態 | 根拠なくFWを変更 |
| 名前で接続できない | ホスト名、発生範囲 | DNS設定、名前解決、キャッシュ | DNSレコードを無断変更 |
| IPが取得できない | IP設定、リンク状態 | DHCPリース、スコープ、VLAN | 他端末のIPを流用 |
| DB接続不可 | 接続先、アプリ側エラー | DB稼働、NW経路、ポート、認証、接続数 | 本番DBを無断再起動 |
| DBが遅い | いつから、対象SQL/画面 | 実行計画、ロック、CPU/IO、変更履歴 | 根拠なくINDEX追加/削除 |
| ディスク容量不足 | 使用率、増加傾向 | ログ、バックアップ、データ増加 | 何が必要か不明なまま削除 |
| ログイン不可 | ID、エラー、他サービス | ロック、期限、MFA、認証基盤 | パスワードを聞き出す |
| 不審メール | 開封/クリック/入力の有無 | メールヘッダー、URL、端末アラート | 転送や再クリックで拡散 |
| マルウェア疑い | 検知内容、端末、時刻 | EDR、SOC、隔離状態 | 独断で証拠削除・初期化 |

## ワークフロー索引
### WF-001 問合せ受付
受付 → 本人/対象確認 → 事象と発生時刻を記録 → 影響範囲/緊急度判定 → ナレッジ検索 → 対応または担当へ引継ぎ → 利用者確認 → チケット完了。

### WF-002 障害対応
検知/受付 → 初動と影響範囲確認 → 重大度判定 → 関係者連絡 → ログ/証拠保全 → 原因切り分け → 承認済み復旧 → サービス確認 → 報告 → 再発防止。

### WF-003 入社アカウント発行
人事/上長申請 → 本人・所属・開始日確認 → 標準ロール確認 → 必要最小限の権限を承認 → ID作成/MFA登録 → PC/メール/VPN設定 → 利用確認 → 台帳・証跡保存。

### WF-004 退職・異動
正式通知 → 対象ID/日時確認 → 停止/権限変更の承認 → 指定時刻にアクセス停止 → セッション/トークン等の扱いを規程に従い処理 → データ所有者へ引継ぎ → 端末回収 → 台帳更新・記録。

### WF-005 権限追加・変更
申請 → 業務上の必要性確認 → データ所有者/上長承認 → 最小権限・期限設定 → 付与 → 申請者確認 → 定期棚卸し。

### WF-006 システム変更
変更申請 → 目的/対象/影響調査 → リスク・停止時間評価 → テスト → 承認 → バックアップ/戻し手順確認 → 作業 → 動作/監視確認 → 完了報告・構成情報更新。

### WF-007 バックアップ確認・復元
対象/スケジュール確認 → 実行結果確認 → 失敗時チケット化 → 原因/再実行承認 → 復元要請時は対象時点/復元先/承認確認 → 隔離環境等で復元検証 → データ整合性/業務確認 → 証跡保存。

### WF-008 セキュリティ事故
疑い/検知 → 直ちに社内窓口へ報告 → 指示に基づく封じ込め → 証拠/ログ保全 → 影響範囲・漏えい有無調査 → 根絶/復旧判断 → 関係者連絡 → 再発防止・記録。法令/顧客報告の判断は責任者が行う。

### WF-009 報告書作成
事実と推測を分ける → 時系列を作る → 影響範囲を明記 → 実施した確認/操作を列挙 → 現在状態を記載 → 未確定事項と次アクションを明記 → レビュー/提出。

### WF-010 再発防止
暫定復旧 → 根本原因分析 → 再発条件の特定 → 恒久対策の担当/期限設定 → テスト → 手順書/監視/教育へ反映 → 効果確認。

## 現場で使う回答例
| 質問 | 短く正確な回答 |
|---|---|
| DNSとは？ | ホスト名やドメイン名をIPアドレスに対応付ける仕組みです。 |
| DHCPとは？ | 端末へIPアドレスなどのネットワーク設定を自動配布する仕組みです。 |
| 認証と認可の違いは？ | 認証は本人確認、認可は許可された操作範囲の判断です。 |
| INDEXとは？ | DB検索を効率化する構造です。読み取りが速くなる一方、更新負荷や容量が増えることがあります。 |
| RPOとRTOの違いは？ | RPOは許容データ損失、RTOは許容復旧時間です。 |
| VPNとは？ | 公衆網などを通じて、認証・暗号化された接続を確立する技術です。 |
| Firewallとは？ | 定義されたルールに基づいてネットワーク通信を許可/拒否する仕組みです。 |
| ログを残す理由は？ | 障害原因、操作履歴、セキュリティ事象を追跡し、監査や再発防止に使うためです。 |

## AI-HUBへの取り込み・接続前メモ
- 辞書パックは `knowledge-packs/it-operations.json` を使用。
- AI-HUBの「根拠にできる知識」→「辞書パック」→「ファイルから読み込む」でJSONを選ぶ想定。
- 取り込み後、索引コード（例 NW-002）と用語（DNS）の両方で検索テストを行う。
- 現在は手動インポート用の初期データ。クラウド同期や自動検索接続はまだ設定していない。
- 社内固有のホスト名、IP、アカウント、秘密鍵、パスワード、顧客情報は公開リポジトリに登録しない。
